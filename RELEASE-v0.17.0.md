# Gapsy CRM v0.17.0 — Головна під роль

За результатами опитування команди (листопад 2026). Перший екран тепер різний для кожної ролі, а «Сьогодні» збирає все, що треба зробити, в одному місці.

## Що нового

**Головна під роль.** Блоки й порядок залежать від ролі:

| Роль | Порядок на Головній |
|---|---|
| Дизайнер | Сьогодні · Мої задачі в ClickUp · Мої проєкти · Правки й документи · Закріплене · Баланс |
| Арт-директор | Сьогодні · Чекають погодження · Задачі · Мої проєкти · Правки й документи · Закріплене · Баланс |
| Розробник | Сьогодні · Задачі · Мої проєкти · Правки й документи · Закріплене · Баланс |
| PM | Сьогодні · Ліди від Sales · Пульс агенції · Задачі · Правки й документи · Закріплене · Баланс |
| Sales | Сьогодні · Мої ліди · Закріплене · Швидкі розділи · Задачі · Баланс |
| Admin (CEO) | Сьогодні · Пульс · Погодження · Ліди · Задачі · Закріплене · Правки й документи · Баланс |

**«Сьогодні»** — для всіх: особисті нагадування (кнопка «+ Нагадування», галочка «Готово»), правки на мені з терміном до післязавтра, хендоффи (прийняти / повернуті), етапи моїх проєктів, що закінчуються, задачі ClickUp на сьогодні й прострочені, а також лічильники: дизайн на погодженні (арт-директор, admin), запити на відпустку (той, хто погоджує), нові ліди (PM, admin).

**Мої задачі в ClickUp** — відкриті задачі, де людина виконавець; лише перегляд, клік відкриває ClickUp. Людину шукаємо за ClickUp-поштою з адмінки або поштою входу.

**Роль Sales.** Нова роль; входить у команду. Головна Sales: «Передати в PM» (бриф, бюджет, дедлайн, посилання) і статус своїх лідів. PM отримує сповіщення, бере лід (створюється проєкт на етапі «Бриф», PM — у команді) або відхиляє з коментарем; Sales бачить рішення.

**Спільні доступи.** PM/admin ставить у сервісі галочку «Спільний акаунт» — тоді пароль бачить уся команда без запиту. Кожен перегляд пишеться в журнал. Позначку змінює лише PM/admin (через RPC, колонку напряму не змінити). У картці — «Пароль змінено N днів тому».

**Нотатки проєкту з типом.** Нотатка · Рішення · Коментар клієнта · Вибір клієнта, плюс посилання на джерело (Slack, ClickUp, лист). Фільтр «Усе / Рішення / Від клієнта». «Вибір клієнта» завжди вгорі.

## Що зробити (по порядку)

1. **Supabase → SQL Editor:** запусти `016a_sales_role.txt` (окремо, один Run).
2. Потім `016_home_roles.txt`.
3. **Supabase → Edge Functions → Deploy new function** `my-tasks`, код — `supabase/functions/my-tasks/index.ts`. Секрет `CLICKUP_TOKEN` уже є (від leave-sync). Необовʼязково: `CLICKUP_TEAM` — id робочого простору.
4. Онови `leave-sync` (додано роль sales у синхронізацію балансу) — не терміново.
5. Залий файли в GitHub і створи тег `v0.17.0`.
6. Я оновлю Head (`@v0.17.0` + стилі блоку 12) і опублікую сайт.

> Важливо: SQL — до тегу. Без колонки `is_shared` сторінка «Доступи» на новому коді не завантажить список.

## Для адміна після релізу

- Адмінка → Користувачі → Маша → роль **Sales** (варіант зʼявляється в списку автоматично).
- Доступи → позначити спільні акаунти (Figma, Freepik, AI-сервіси…).
- Якщо в когось «Не знайшли тебе в ClickUp» — вписати ClickUp-пошту в профілі людини.

## Технічно

- `crm-core.js`: `STAFF` + sales; `CRM.homeRole()` (art для арт-директора).
- `modules/dashboard.js`: картки `[data-home="today|tasks|projects|reviews|leads|links"]` створює JS на класах із Designer; наявні блоки лише переставляються.
- `modules/access.js`: `is_shared`, чекбокс у формі, RPC `access_set_shared`.
- `modules/project.js`: `kind`, `link`, фільтр `[data-notes-filter]`.
- `modules/admin.js`: роль sales у бейджах і select.
- SQL: `is_staff()` з sales; `access_items.is_shared` + тригер-запобіжник + `access_reveal` для спільних; `reminders` (RLS: лише свої); `project_notes.kind/link`; `leads` + `lead_notify` + `lead_decide`.
- Стилі (блок 12) — `webflow/home-v017.css`, живуть у Site Head.
- Тест: `test/smoke22.js` (6 ролей, нагадування, ClickUp, ліди, спільні доступи, нотатки). Попередні смоуки без змін поведінки.
