# Gapsy CRM v0.4.0: Моя робота і Правки 2.0

## Що нового

- **Моя робота** (`/my-work`, пункт меню після «Головної»): чотири блоки.
  - Правки на мені: сортування за пріоритетом, потім за дедлайном.
  - Хендоффи, що чекають саме на мене.
  - Створені мною правки, які виконує хтось інший.
  - Мої активні проєкти з кількістю відкритих правок.
  - Угорі підсумок, наприклад «2 правки на тобі · 1 прострочена · 1 хендофф чекає».
- **Пріоритет і дедлайн правки:** Низький / Звичайний / Високий / Терміново, плюс дата.
  - Поля є у формі нової правки і в боковій картці правки; там зміни зберігаються одразу.
  - У списках «Терміново» червоне, «Високий» жовтий, «Звичайний» не показується.
  - Дедлайн жовтий, коли настає сьогодні або завтра, і червоний, коли прострочений.
  - Новий таб «Прострочені» з лічильником.
  - Виконавець отримує сповіщення, коли правку зробили терміновою або змінили дедлайн.
- **Позначки на скрінах:**
  - Відкрий скрін і клікни в потрібне місце, з'явиться чорний пін. Напиши, що змінити, і натисни «Додати позначку».
  - Позначки нумеруються 1, 2, 3… і показуються списком під скрінами.
  - Галочка позначає виконане (пін стає сірим). Клік по номеру відкриває скрін і підсвічує пін.
  - На мініатюрі скріна видно кількість невиконаних позначок.
  - Позиція зберігається у відсотках, тож пін стоїть на місці за будь-якої ширини екрана.

## Хто що може (RLS)

| Дія | Хто |
|---|---|
| Бачити й ставити позначки | уся команда |
| Відмітити позначку виконаною | уся команда (як статус правки) |
| Змінити текст позначки | автор позначки, PM, admin |
| Видалити позначку | автор позначки, PM, admin |
| Зсунути пін / перенести на інший скрін | ніхто (заборонено на рівні колонок) |

## Кроки

1. **Supabase → SQL Editor → New query.** Встав увесь `004_feedback2_mywork.sql` і натисни Run. Має бути «Success. No rows returned».
2. **GitHub → репо gapsy-crm.**
   - У корені: Add file → Upload files → `crm-core.js`, `004_feedback2_mywork.sql`, `RELEASE-v0.4.0.md` → Commit.
   - У папці `modules`: Add file → Upload files → `my-work.js`, `feedback.js`, `feedback-item.js` → Commit.
   - За бажанням: оновити `test/`.
3. **Releases → Draft a new release → тег `v0.4.0`** → Publish.
4. Напиши мені «тег є». Я перевірю файл на jsDelivr, переключу Head на `@v0.4.0` і опублікую сайт.

**Webflow не публікуй до кроку 4.** Розмітка v0.4 уже в Designer. Зі старим кодом нові бейджі показували б текст-заглушку («Терміново», «Завтра»).

## Що перевірити після публікації

- Меню: є «Моя робота», сторінка відкривається, підсумок угорі відповідає даним.
- `/feedback`: створи правку з пріоритетом «Високий» і дедлайном на завтра. У списку жовті бейджі, правка вгорі відкритих.
- Картка правки: зміни пріоритет на «Терміново». Виконавець має отримати сповіщення «Терміново: …».
- Позначки:
  - відкрий скрін, клікни → напиши → «Додати позначку»;
  - пін на місці після зміни розміру вікна;
  - галочка робить пін сірим;
  - номер у списку відкриває скрін.
- Мобільний 479: лайтбокс з панеллю знизу прокручується, пін ставиться тапом.

## Обмеження (свідомо, щоб не перемудровувати)

- Поставити позначку можна лише мишею або тапом. З клавіатури можна переглядати, відмічати й видаляти.
- Дедлайн — дата без часу. «Прострочено» рахується від початку наступного дня за часом браузера.
